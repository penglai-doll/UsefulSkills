# Attack Analysis v1.0.0 设计规格

**状态：** 已批准，待实施
**日期：** 2026-07-10
**目标版本：** 1.0.0

## 1. 背景

`attack-analysis` 0.1.0 已具备日志盘点、parser 插件、候选事件提取、基础关联和 Markdown 报告契约，但仍属于可运行原型：日志类型判断集中在 `inventory_logs.py`，嗅探读取量与判断依据不匹配；parser 达到候选数量上限后会停止扫描；XLSX 读取不是流式；攻击语义部分由脚本提前命名；报告输出位于 skill 内部目录，且缺少落盘与证据一致性验证。

v1.0.0 将升级为 AI 主导的日志调查工作流。脚本只承担透明、确定、可复核的机械处理，尤其是大文本的全量流式过滤、降噪、索引和上下文提取。攻击性质、攻击链、因果关系、入侵是否成功及最终报告结论全部由 AI 判断。

## 2. 目标

1. 在不全量读取日志的前提下，通过有界特征嗅探建议日志类型。
2. 类型识别为高置信度时自动采用；非高置信度、格式冲突或缺少 parser 时询问用户。
3. 类型确定后完整流式扫描日志，不因候选数量达到上限而漏掉文件后段事件。
4. 通过透明降噪、聚合和索引减少 AI 上下文，而不是让脚本替代分析。
5. 允许 AI 随时推翻类型建议、检查过滤摘要并补取原始上下文。
6. 将缓存和 Markdown 报告输出到调用 skill 时的当前工作目录。
7. 保持 `quick-report` 与 `interactive` 的工作前模式确认门禁。
8. 用长日志尾部攻击、混合格式、多时区、损坏文件和端到端攻击链验证工作流。

## 3. 非目标

- 不构建实时 SIEM、告警平台或主动防御系统。
- 不由脚本判定攻击成功、攻击者身份、漏洞利用成立或因果关系。
- 不输出威胁评分、风险总分、数字化等级或相似指标。
- 不在 v1.0.0 宣称完整支持 Windows EVTX、云审计、Kubernetes、二进制 MySQL/MariaDB binlog、PCAP、内存或磁盘镜像。
- 不自动安装工具、下载情报数据库、修改防火墙或生产系统。
- 不向外部服务上传完整日志、凭据、请求体、数据库结果或内部业务参数。

## 4. 已确认的版本边界

### 4.1 v1.0.0 重点支持

- Apache、nginx 及常见 combined/common Web access 日志；无法可靠区分产品时使用中性的 `web_access`。
- Spring Boot 应用日志。
- P6Spy SQL 日志，以及嵌入 Spring 日志的 P6Spy 记录。
- XLSX 登录和操作记录导出。
- Linux auth、system/service、firewall、WAF 文本日志。
- `mysqlbinlog` 已导出的文本。
- JSON、JSONL、CSV 和未知文本的通用特征识别及保守提取。

### 4.2 后续扩展

- Windows EVTX、AD、Sysmon。
- AWS、Azure、GCP、阿里云、腾讯云、华为云审计体系。
- Kubernetes 和容器多源取证。
- 二进制 MySQL/MariaDB binlog 深度重建。
- PCAP、内存、磁盘镜像和专有 EDR 格式。

## 5. 核心原则：AI 主导，脚本降噪

### 5.1 脚本允许承担的职责

- 文件发现、大小和修改时间盘点。
- magic bytes、扩展名、压缩格式、编码和结构特征探测。
- 有界读取日志特征并给出候选类型。
- 全文件流式扫描、机械过滤、聚合计数和索引。
- 标准化时间、IP、端口和代理链，同时保留原始值。
- 按文件、行号、时间、IP、账号、URL 或其他机械键提取上下文。
- 生成相同键和相近时间窗口的关联候选。
- 写入缓存、检查报告文件和验证结构性约束。

### 5.2 脚本禁止承担的职责

- 输出“攻击已确认”“攻击成功”“高危攻击者”等结论。
- 将规则命中直接解释为 SQL 注入、命令执行、权限获取或数据泄露成立。
- 给攻击、IP、事件或服务器打威胁分数和风险等级。
- 在缺少原始证据时断言跨日志因果关系。
- 生成或改写最终调查结论。

### 5.3 AI 职责

- 复核并可推翻日志类型建议。
- 检查扫描摘要、过滤规则和被降噪记录的代表样本。
- 阅读候选记录和原始上下文，区分正常业务、噪声、探测、利用和成功入侵。
- 主动要求补取指定时间、IP、账号、URL、行号或候选类别的原文。
- 复核机械关联候选，建立或否定调查假设。
- 区分日志直接事实、跨日志关联、外部情报、AI 推断和未确认事项。
- 维护证据台账并编写最终 Markdown 报告。

脚本输出使用中性词汇，例如 `http_request`、`sql_record`、`auth_record`、`operation_record`、`matched_signals` 和 `filter_reason`。现有 `web_probe`、`sql_suspicious` 等偏结论式事件名称在实施时改为中性记录类型。

## 6. 组件架构

```text
attack-analysis/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── references/
│   ├── workflow.md
│   ├── log-types.md
│   ├── correlation.md
│   ├── reporting.md
│   ├── error-handling.md
│   ├── ip-enrichment.md
│   └── validation.md
├── scripts/
│   ├── inventory_logs.py
│   ├── extract_log_events.py
│   ├── extract_context.py
│   ├── correlate_events.py
│   ├── validate_report.py
│   ├── detectors/
│   ├── parsers/
│   └── common/
└── tests/
```

### 6.1 `detectors/`

每个 detector 只读取传入的有界样本并返回候选类型、命中特征和置信度。detector 不读取整个文件，也不判断攻击行为。建议按文本签名、结构化文本和 XLSX 分离模块，通过统一 registry 调度。

### 6.2 `inventory_logs.py`

负责文件发现、生成有界样本、调度 detector、记录文件元数据并写入 manifest。它不内嵌所有格式规则。生成目录清单时必须排除当前工作目录下的 `cache/` 和 `report/`。

### 6.3 `extract_log_events.py`

保留现有入口名称以减少兼容性破坏，但内部语义调整为流式提取中性记录候选。它调度 parser，将候选逐条写入 JSONL，并在扫描结束后写入完整性统计。任何候选数量限制只能限制 AI 展示批次，不能停止底层扫描。

### 6.4 `extract_context.py`

按文件和位置补取原始证据，支持行号范围、时间窗口、IP、账号、URL 和候选类别。输出必须包含来源文件、起止行或 XLSX 行号、编码状态及原始片段。该脚本是 AI 的检索工具，不作分析判断。

### 6.5 `correlate_events.py`

仅根据相同 IP、账号、session、request ID、URL、线程、SQL 关联键和时间窗口生成候选组合。输出状态固定为 `candidate`，不声明因果关系。

### 6.6 `validate_report.py`

只检查：报告存在且可读、必需章节齐全、证据 ID 在台账中存在、禁用评分词未出现、文件已写入预期目录。它不生成报告，不评价结论是否正确，也不修改 AI 文本。

## 7. 输出布局

所有产物以调用 skill 时的 `$PWD` 为根目录：

```text
$PWD/
├── cache/
│   └── <case-id>/
│       ├── analysis-manifest.json
│       ├── detection-results.json
│       ├── scan-summary.json
│       ├── record-candidates.jsonl
│       ├── correlation-candidates.json
│       └── evidence-ledger.json
└── report/
    └── <case-id>/
        └── log-analysis-report.md
```

- `<case-id>` 默认由首个日志目录的安全化名称和本地时间生成，允许用户指定。
- 相同 `<case-id>` 已存在时不得静默覆盖；生成新 ID，或在用户明确允许后覆盖。
- manifest 记录 `invocation_cwd` 和所有输出的绝对路径。
- 报告先写同目录临时文件，通过落盘检查后原子替换最终文件。
- 最终回复返回报告的绝对路径和简短结论。

## 8. 工作流

```text
模式确认
  -> 日志路径
  -> 有界类型嗅探
  -> 必要时类型确认
  -> manifest
  -> 全文件流式过滤和统计
  -> AI 初审
  -> 按需提取原始上下文
  -> 机械关联候选
  -> AI 建立或否定攻击链
  -> 按需联网富化
  -> AI 维护证据台账
  -> AI 写 Markdown 报告
  -> 结构与落盘验证
```

### 8.1 模式门禁

调用 `/attack-analysis` 后，除非当前用户请求已经明确指定，否则必须先询问 `quick-report` 或 `interactive`。模式确认发生在 inventory、解析、联网和报告生成之前，不能从紧急程度、文件路径或之前会话静默推断。

### 8.2 `quick-report`

- 只要求确认模式和日志路径。
- 高置信度类型自动采用；所有非高置信度、冲突和无 parser 的文件集中询问一次。
- 默认完成全部已纳入日志的轻量全文件流式初筛，不因文件大而随机抽样。
- 如果用户明确提供时间范围，可以只扫描该范围，但必须在报告中说明。
- AI 完成一轮主要复核，并自动补取关键候选上下文。
- 生成第一版报告，未解决问题标记为待补证。

### 8.3 `interactive`

- 在嗅探后允许修正逐文件类型、时区和 include 状态。
- 允许指定时间范围、关注 IP、账号、URL 和调查问题。
- AI 分轮建立、验证或否定假设，并按证据主动扩大或缩小检索范围。
- 用户可以在最终报告前继续调整分析范围。

## 9. 有界日志类型嗅探

### 9.1 采样预算

1. 先检查扩展名、magic bytes、压缩格式和 BOM。
2. 默认读取文件头最多 `128 KiB` 或前 `500` 条记录，以先到者为准。
3. 普通可 seek 文本在识别不明确时，可补读尾部 `128 KiB` 和一个中段 `64 KiB` 切片。
4. `.gz` 在识别阶段最多扩展到解压后 `1 MiB`，不得为了尾部特征解压完整文件。
5. XLSX 只读取 ZIP 目录、工作簿结构、目标表头和前 `50` 行；必须使用流式 XML，不能将整张 worksheet XML 载入内存。

这些预算是默认上限。实现可以暴露显式参数供测试或特殊案件调整，但 skill 不应在普通调用中要求用户选择字节数。

### 9.2 detector 输出契约

```json
{
  "primary_type": "spring_app",
  "candidate_types": ["p6spy_sql"],
  "confidence": "high",
  "matched_features": [
    "timestamp_level_thread_logger",
    "embedded_p6spy_records"
  ],
  "bytes_sampled": 131072,
  "records_sampled": 420,
  "needs_confirmation": false
}
```

- `confidence` 仅表示格式识别置信度，不表示威胁等级。
- `matched_features` 必须可解释，不只返回黑盒分数。
- 高置信度自动采用；非高置信度、候选冲突、声明类型冲突和 parser 缺失触发确认。
- 无法可靠区分 Apache 与 nginx 时使用 `web_access`，不得制造虚假精度。
- Spring/P6Spy 等混合文件允许多个 parser profile，但同一原始行只能产生一个主记录；附加解析结果写入该记录的结构化字段。

## 10. 全文件流式过滤与降噪

有界采样只用于判断格式，不用于搜索攻击。类型确定后，脚本默认从头到尾顺序扫描所有纳入范围的记录。

### 10.1 完整性规则

- parser 逐行或逐记录处理，不能将完整文件载入内存。
- `record-candidates.jsonl` 逐条写入磁盘，不能先聚合到 Python 大列表。
- 达到候选展示上限后仍继续扫描并记录候选；展示分页和底层扫描相互独立。
- `.gz` 在分析阶段顺序解压并扫描完整内容。
- 每个文件记录 `bytes_scanned`、`records_scanned`、`scan_status`、`decode_error_count`、扫描前后大小和修改时间。
- 磁盘空间不足导致候选缓存不完整时，可以继续聚合统计，但必须将状态标记为 `partial_cache`，AI 不得宣称完整候选集已保存。

### 10.2 透明降噪

可聚合的机械噪声包括高频静态资源、固定健康检查、完全重复记录、已知固定爬虫和重复应用错误。降噪结果必须保存：

- 过滤规则标识；
- 总记录数和时间分布；
- 按 IP、路径、账号、结果等维度的聚合；
- 每个时间桶的确定性代表样本；
- 原始文件和可恢复位置。

脚本保留异常方法、状态变化、罕见路径、超长参数、编码载荷、认证结果、SQL 操作和应用异常等记录，但这些只是候选，不是攻击结论。为了降低未知攻击被固定规则掩盖的概率，罕见组合必须保留，例如常见路径配合罕见方法、常见账号配合新来源 IP、静态路径配合异常状态变化。

AI 必须可以查看过滤策略和代表样本，并通过 `extract_context.py` 恢复任意过滤类别的原始记录。

## 11. AI 调查流程

AI 按以下顺序工作：

1. 阅读 manifest、类型识别依据和扫描完整性状态。
2. 建立每种日志的正常基线，包括时间分布、主要来源、常见路径、结果和业务行为。
3. 检查候选记录、罕见组合、过滤摘要和代表样本。
4. 对关键候选补取原始前后文，避免只看孤立行。
5. 阅读机械关联候选，并用原始证据验证连接字段、时间窗口和业务连续性。
6. 建立、修正或否定攻击假设。
7. 仅在本地证据形成调查方向后，联网查询 IP、ASN、运营商、初步地理位置、公开漏洞和扫描器特征。
8. 维护 `evidence-ledger.json`，再据此编写报告。

证据台账将结论来源标记为：日志直接事实、跨日志关联、外部公开情报、AI 分析推断或尚未确认。IP 定位和 ASN 不能单独用于认定攻击者身份。

## 12. 关联候选

脚本可按以下机械键生成候选：

- 标准化 IP 和代理链成员；
- 账号、登录名和业务用户标识；
- session、request ID、trace ID；
- URL、路由、资源路径和操作对象；
- 应用线程、logger 和 SQL 上下文；
- 相同或相近时间窗口。

每个候选包含参与记录、匹配依据、时间差和原始来源，状态固定为 `candidate`。AI 只有在连接键可靠、时间顺序合理、上下文支持且不存在更合理解释时，才能将其写入攻击链。仅有相近时间或共享公共 IP 时不能宣称因果关系。

## 13. Markdown 报告

默认使用中文，除非用户明确要求其他语言。固定输出到：

```text
$PWD/report/<case-id>/log-analysis-report.md
```

必需章节：

1. 摘要结论。
2. 分析范围与日志类型识别结果。
3. 时间范围、时区和日志缺口。
4. 攻击来源 IP、ASN、运营商、初步定位及查询来源。
5. 完整攻击时间线。
6. 攻击方式与实现过程。
7. 跨日志证据链。
8. 是否存在成功入侵的证据判断。
9. 关键证据表。
10. 当前存在的问题。
11. 立即处置、短期修复和长期加固建议。
12. 不确定性、缺失日志和待补证事项。

每个实质性结论必须关联证据 ID。报告明确区分日志事实、外部情报和 AI 推断；证据不足时使用“未确认”“无法判断”或“需要补充”，不得把候选关联写成确定事实。

## 14. 异常与边界处理

### 14.1 类型和格式

- 用户声明与检测冲突时同时保留，AI 决定实际 parser profile。
- 混合格式允许多个 profile，但按原始位置去重。
- 未知文本进入通用流式索引，不强制归类。
- 不支持的二进制记录元数据和限制，不尝试通用文本解析。

### 14.2 编码、压缩和损坏

- 检查 BOM、UTF-8、GB18030 等常见编码，记录替换字符和解码异常。
- 损坏 `.gz` 保留错误前结果，并标记扫描不完整。
- 多行堆栈、SQL 和应用错误保存起止行号。
- XLSX 损坏、缺少表头或工作表异常不影响其他文件。

### 14.3 时间和 IP

- 每个文件独立记录 `explicit`、`inferred` 或 `unknown` 时区状态。
- 未知时区事件不由脚本强行排序成因果链。
- 保留原始 IP、端口、IPv6、代理链和标准化字段。
- 未确认代理配置前，不从 `X-Forwarded-For` 武断选择攻击源。

### 14.4 扫描和输出

- 扫描前后比较文件大小和修改时间，记录源文件是否发生变化。
- 部分扫描、部分缓存和完整扫描使用不同状态，不得混淆。
- 自动排除 `$PWD/cache/` 和 `$PWD/report/`。
- 报告写入或验证失败时不声称成功。
- 联网失败自动离线继续，并记录未完成的富化项目。

## 15. 测试设计

### 15.1 类型识别矩阵

为 Web access、Spring、P6Spy、混合 Spring/P6Spy、auth、system、firewall、WAF、mysqlbinlog 文本、JSON、JSONL、CSV、XLSX、gzip、无扩展名、错误扩展名、乱码、未知文本和二进制建立脱敏 fixture。验证候选类型、命中特征、采样预算、确认门禁和未知格式保守处理。

### 15.2 长日志尾部攻击

动态生成至少 100,001 行日志，在第 50,001 和 100,001 行放置候选。普通文本和 gzip 均验证：两个候选都被发现、扫描记录数完整、候选上限不导致提前停止、内存不随日志行数线性增长。

### 15.3 降噪透明度

验证重复噪声被聚合而不是无记录删除；每个过滤类别有计数、时间分布和代表样本；罕见组合不会被静态资源规则掩盖；AI 可按类别恢复原文；脚本输出没有攻击结论和威胁评分。

### 15.4 端到端金标准案例

扩展现有 gold fixture，覆盖扫描探测、认证尝试、异常登录、应用调用、SQL 操作和文件上传或敏感操作，同时加入多时区、代理 IP 链、正常管理员操作、无法稳定关联的干扰事件及至少一个应被 AI 否定的伪攻击候选。

验收不要求报告逐字一致，但要求关键证据不遗漏、正常行为不误入攻击链、证据不足时不宣称成功入侵、时间线和证据编号一致。

### 15.5 输出和失败场景

验证当前目录输出、重复运行不覆盖、cache/report 自排除、必需章节、证据 ID、禁用评分词、联网失败、损坏 gzip、乱码、时间未知、源文件变化和写入失败。真实样本只用于本地回归，不进入 Git。
